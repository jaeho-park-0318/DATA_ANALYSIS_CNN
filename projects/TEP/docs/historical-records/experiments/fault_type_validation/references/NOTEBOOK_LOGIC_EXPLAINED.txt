# DL_TEP 노트북 로직 설명

이 문서는 `DL_TEP_Sequence_Prediction_Classification.ipynb`를 읽으면서 각 코드가 왜 필요한지 이해하기 위한 설명서입니다.

노트북의 큰 목표는 다음과 같습니다.

1. TEP 공정 데이터를 불러온다.
2. 정상 구간 데이터로 다음 시점 feature를 예측하는 Forecaster를 학습한다.
3. Forecaster의 예측값을 이용해 고장 번호를 분류하는 Classifier를 학습한다.
4. 저장된 모델을 재사용해 예측, 분류, 잔차분석을 수행한다.

## 전체 구조

노트북에는 크게 세 가지 흐름이 있습니다.

| 흐름 | 역할 |
| --- | --- |
| TensorFlow/Keras 흐름 | Forecaster와 Classifier를 Keras로 학습하고 저장 |
| PyTorch 통합 흐름 | 같은 아이디어를 PyTorch 코드로 한 번에 실행할 수 있게 정리 |
| 저장 모델 잔차분석 흐름 | 이미 학습된 Keras Forecaster만 불러와 RMSE 잔차분석 수행 |

## 핵심 개념

### Forecaster

Forecaster는 시계열 예측 모델입니다.

입력:

```text
직전 WINDOW_SIZE개 시점의 공정 변수
```

출력:

```text
다음 시점의 공정 변수
```

예를 들어 `WINDOW_SIZE = 10`이면, 10개 시점의 `xmeas_*`, `xmv_*` 값을 보고 11번째 시점의 값을 예측합니다.

### Classifier

Classifier는 고장 번호를 맞히는 분류 모델입니다.

이 노트북에서는 Classifier 입력을 다음처럼 만듭니다.

```text
직전 실제 feature + Forecaster가 예측한 다음 feature
```

즉, 공정의 현재 상태와 다음 상태 예측을 함께 보고 faultNumber를 맞히게 합니다.

### RMSE 잔차분석

잔차는 다음과 같습니다.

```text
residual = 실제값 - 예측값
```

RMSE는 잔차의 크기를 요약한 값입니다.

```text
RMSE = sqrt(mean(residual^2))
```

모델 성능 관점에서는 RMSE가 낮을수록 좋습니다.  
이상진단 관점에서는 RMSE가 높은 구간이나 높은 변수를 우선 확인합니다.

## Cell 10. Forecaster용 시계열 데이터셋 생성

```python
WINDOW_SIZE = 10
```

과거 몇 개 시점을 보고 다음 시점을 예측할지 정합니다.

```python
GROUP_COLS = [c for c in ["faultNumber", "simulationRun"] if c in train_df.columns]
```

데이터를 faultNumber와 simulationRun 단위로 나누기 위한 컬럼 목록을 만듭니다.

```python
def iter_groups(df):
```

데이터를 그룹 단위로 순회하는 함수입니다.

```python
yield from df.groupby(GROUP_COLS, sort=False)
```

그룹 컬럼이 있으면 faultNumber, simulationRun별로 나누어 반환합니다.

```python

```

그룹 컬럼이 없으면 전체 데이터를 하나의 그룹으로 봅니다.

```python
def make_forecast_dataset(...):
```

Forecaster 학습에 필요한 `X`, `y`, `row_indices`를 만드는 함수입니다.

```python
X, y, row_indices = [], [], []
```

입력 sequence, 정답 다음 시점 값, 원본 행 index를 담을 리스트입니다.

```python

```

faultNumber 0이 실제로 존재하는지 확인합니다.

```python
for _, group in iter_groups(df):
```

각 simulation run 또는 fault group을 따로 처리합니다.

```python
group = group.sort_values("sample") if "sample" in group.columns else group
```

시간 순서가 중요하므로 sample 기준으로 정렬합니다.

```python
if len(group) <= window_size:
    continue
```

window보다 짧은 그룹은 sequence를 만들 수 없으므로 건너뜁니다.

```python

```

feature를 scaler 기준으로 표준화합니다.

```python

```

나중에 원본 데이터 위치를 추적하기 위해 index를 저장합니다.

```python

samples = group["sample"].to_numpy() ...
```

정상 구간 판단을 위해 faultNumber와 sample 값을 배열로 만듭니다.

```python

```

window 크기 이후부터 한 칸씩 움직이며 학습 샘플을 만듭니다.

```python

```

현재 예측 대상 시점이 정상인지 판단합니다.


```python
y.append(values[i])
```

현재 시점 feature를 정답으로 넣습니다.

```python
row_indices.append(idx_values[i])
```

정답 시점의 원본 행 index를 저장합니다.

```python

```

리스트를 numpy 배열로 변환해 모델 학습에 사용할 수 있게 반환합니다.

선택된 문자열에 따라 실제 layer 클래스를 정합니다.

```python
dense_units = hp.Int(...)
model.add(layers.Dense(dense_units, activation="relu"))
```

```python
model.add(layers.Dense(n_features, activation="linear"))
```

### PyTorch Forecaster

```python
class Forecaster(nn.Module):
```

PyTorch 방식의 다음 시점 예측 모델입니다.

```python
self.lstm = nn.LSTM(...)
```

과거 sequence를 읽는 LSTM layer입니다.

```python
self.head = nn.Sequential(...)
```

LSTM 마지막 출력에서 다음 feature 벡터를 예측하는 Dense head입니다.

```python
def forward(self, x):
    out, _ = self.lstm(x)
    return self.head(out[:, -1, :])
```

입력 sequence를 LSTM에 넣고, 마지막 시점의 hidden state로 다음 feature를 예측합니다.

### PyTorch Classifier

Classifier 클래스는 Keras Classifier와 같은 목적입니다.

입력은 `직전 실제 feature + Forecaster 예측 feature`입니다.

출력은 fault class logits입니다.

Keras의 softmax 출력과 달리 PyTorch에서는 보통 `CrossEntropyLoss`가 내부적으로 softmax 역할을 포함하므로 모델 마지막에서 softmax를 직접 하지 않습니다.

### 학습 루프

PyTorch에서는 Keras의 `model.fit()` 대신 직접 학습 루프를 작성합니다.

일반 흐름은 다음과 같습니다.

```text
model.train()
batch 반복
prediction = model(x)
loss = criterion(prediction, y)
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

검증은 다음 흐름입니다.

```text
model.eval()
torch.no_grad()
검증 prediction 계산
검증 loss 또는 metric 계산
```

early stopping은 검증 지표가 좋아지지 않는 epoch 수를 세다가 patience를 넘으면 학습을 멈추는 방식입니다.

### 저장

PyTorch 모델은 `.pt` 파일로 저장됩니다.

```python
torch.save(model.state_dict(), ...)
```

모델 구조 자체가 아니라 학습된 weight만 저장합니다.

따라서 다시 불러올 때는 같은 모델 클래스를 만든 뒤 `load_state_dict`로 weight를 넣어야 합니다.

## 이해 확인 문제

### 문제 1

`StandardScaler`를 전체 train 데이터가 아니라 정상 구간 데이터에 `fit`하는 이유는 무엇인가요?

### 문제 3

RMSE는 낮을수록 좋은 지표인데, 잔차분석 표에서는 왜 feature별 RMSE를 높은 순으로 정렬했나요?

### 문제 5

## 정답 및 해설

### 정답 1

정상 상태의 평균과 표준편차를 기준으로 scaling해야 이상 구간이 정상 기준에서 얼마나 벗어났는지 보기 쉽기 때문입니다.  
전체 데이터로 scaler를 학습하면 이상 구간의 값까지 평균과 표준편차에 섞여 정상 기준이 흐려질 수 있습니다.

### 정답 2

Forecaster의 `X`는 과거 `WINDOW_SIZE`개 시점의 feature sequence이고, `y`는 그 다음 시점의 feature입니다.  
`WINDOW_SIZE = 10`이면 1번부터 10번 시점까지 보고 11번 시점의 `xmeas_*`, `xmv_*` 값을 예측합니다.

### 정답 3

직전 실제 feature는 현재 공정 상태를 나타내고, Forecaster 예측 feature는 다음 시점의 정상 패턴 기대값을 나타냅니다.  
이 둘을 함께 주면 Classifier가 현재 상태와 예측된 다음 상태 정보를 동시에 보고 faultNumber를 판단할 수 있습니다.

### 정답 4

모델 성능 평가에서는 RMSE가 낮을수록 좋습니다.  
하지만 잔차분석에서는 문제가 큰 변수, 즉 예측이 많이 틀린 변수를 먼저 찾는 것이 목적이므로 높은 순으로 정렬합니다.

### 정답 5

TEP 데이터에서 fault run이라도 초기 `sample <= 160` 구간은 고장이 본격적으로 주입되기 전 정상 운전 구간으로 보는 경우가 많기 때문입니다.  
그래서 해당 구간은 faultNumber가 0이 아니어도 정상 class 0으로 처리합니다.
