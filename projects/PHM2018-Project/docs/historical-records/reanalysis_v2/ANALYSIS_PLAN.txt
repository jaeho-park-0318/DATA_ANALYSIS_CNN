# 재분석 계획

## 1. 기존 정책을 가설로 되돌리기

다음 항목은 오류로 확정된 것이 아니라 재검증할 가정이다.

1. 통합 음성에 세 유형 모두 유한 TTF를 요구하는 조건이 필요한가? 유형별 이력 종료와 장비 관측 종료를 구분한다.
2. 관측 공백 12, 과거 이력 600, 밀도 90%, anchor 간격 60이라는 기준이 실제 수집·공정 구조에 맞는가?
3. 고장 이전 센서 공백을 이유로 알려진 미래 이벤트까지 라벨 NA로 만드는 것이 적절한가? 입력 관측 가능성과 라벨 확인 가능성을 별개로 검토한다.
4. 같은 시각 여러 행을 평균내면 공정 상태나 센서 의미가 훼손되는가? 중복 원인부터 확인한다.
5. Stage=0, Recipe=0이 실제로 무엇을 의미하는가? 0을 정지나 정상으로 단정하지 않는다. 기존 Stage>0 노출량도 물리적 가동 시간이라는 해석을 재검토한다.
6. 고장 기록이 이상 발생 시작인지 정비 정지인지 확인한다. 예측 목표의 명칭과 해석에 반영한다.

## 2. 원본 기준 파일·시간·이벤트 재검증

- 원본 문서 및 실제 기록으로 time 단위와 파일별 측정 간격을 확인한다.
- 대표 장비 01M01, 03M02, 04M02를 먼저 조사한다. 각각 기존 연속 구간 사례, 태그/TTF 충돌 사례, 통합 음성 부족 사례를 비교한다. 이 선택은 진단용이며 성능 평가 표본 선정이 아니다.
- CSV를 필요한 열만 청크로 읽고 원본 행 번호를 보존한다.
- 파일·장비·기간·중복·시간 역전·공백·공정 전환을 집계한다.
- 중복 Fault 및 [NoWaferID] 처리 근거와 센서/Fault/TTF 매칭 사례를 표로 만든다.

## 3. 정답 근거와 관측 가능성 분리

- 이벤트 시각, 센서 마지막 관측, TTF 유무, 이력 완전성 근거를 별도 컬럼으로 기록한다.
- TTF Null을 정상으로 바꾸지 않는다. 다만 기존의 일괄 NA 정책도 검증 없이 정답으로 취급하지 않는다.
- 공백 때문에 특징을 계산할 수 없는 상태와 미래 고장 유무를 알 수 없는 상태를 구분한다.
- 유형별/통합 라벨마다 양성·음성·미확인 근거를 명시한다. 근거가 부족한 대안은 민감도 분석용으로만 둔다.
- 초 단위 확인 후 우선 600 구간을 정의한다. 검증 전에는 원시시간 단위로 표기한다.

## 4. 데이터셋 재구축 전 통과 조건

- 원본에서 최종 표본까지 모든 행의 보존·탈락 수와 이유가 합계로 일치한다.
- 장비·Stage·Recipe·고장 유형별 클래스 및 이벤트 보존율을 공개한다.
- 선택한 이벤트의 원본 시계열과 라벨을 대조하고 경계값 테스트를 통과한다.
- 미래 정보는 라벨/평가에만 사용하고 특징에는 포함하지 않는다.
- 음성 없는 장비나 관측 불가 이벤트를 조용히 제외하지 않는다.
- 기존 데이터와 새 정책의 차이를 같은 원본 구간에서 비교한다. 클래스 균형 개선만으로 새 정책을 채택하지 않는다.

## 5. 검증 이후의 모델 계획

현재 센서 중심의 작은 Baseline부터 시작한다. 장비 외부 평가와 시간 외부 평가는 분리하고, 기존에 본 장비·기간의 결과를 새로운 독립 평가라고 부르지 않는다. 특징 확장은 현재 값 → 과거 통계 순서로 비교한다. 임계값은 평가 장비 밖에서 결정한다. 이벤트 탐지, 확인 구간의 오경보율, 미확인 구간 경보량, Lead Time을 함께 보고한다. LSTM은 이번 재검증에 포함하지 않는다.
